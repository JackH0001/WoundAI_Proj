# MMH 稽核讀取排程優化與 Claude 覆核交接

## 本輪來源與驗證

基底 `675ae02591614b044eed552a5882d856a938101f`，含 iOS 登入繁忙重試／送件面積對齊，以及兩平台僅輸出 image、overlay 的修正。本次只改未鎖定模式的稽核讀取排程：保留四個讀取工作者，以最多八個未消費讀取結果的滑動窗口替代四筆一組的等待屏障。

每次 append 仍讀回所有歷史 bytes，使用 generation 條件、按序驗證 hash／prev，並重新查清單；條件建立、寫後讀回、權限及 retention 檢查、錯誤封鎖均保留。沒有省略研究影像、傷口／組織遮罩、原始深度、內參、方向或保存收據。正常成功時物件讀取次數不減，雲端費用不因本改動直接降低。

## 優化前後（離線，不能當成雲端加速承諾）

32 個合成稽核紀錄、相同四個工作者、每種五輪，完整 append 驗證。均勻讀取延遲 2 ms；慢回應情境每四筆有一筆 40 ms。

| 情境 | 舊版中位數 | 新版中位數 | 減少 |
|---|---:|---:|---:|
| 均勻延遲 | 23.57 ms | 20.37 ms | 13.6% |
| 慢回應混合 | 352.93 ms | 181.75 ms | 48.5% |

實際服務先前觀察值：health 熱機 35–44 ms、session 65–83 ms、attest 9.86–11.38 秒、classify 10.81–13.40 秒、annotation 37.43 秒。這不是同負載 A/B；沒有資料可宣稱移除 Google 會縮短多少秒。稽核仍為 O(N) 全量讀取，資料增加仍可能變慢；若要改變這點，需要獨立且可驗證的歷史保護機制，不能直接跳過歷史驗證或延後寫稽核。

## Claude 請覆核

1. 有界窗口是否在例外、消費者終止、世代改變、並行 append 下仍 fail closed；讀取不得在 generator 結束後持續寫入或隱藏錯誤。
2. 新增測試是否能抓到原本四筆屏障，以及窗口無界化的退化；請另做故障注入。
3. `ae75df5` 的 iOS Google GET 重試不應擴大為自動重播 POST；研究送件資料應來自同一保存修訂。
4. `675ae02` 的 iOS／Android 外部輸出只包含兩張圖，overlay 必須含最新已確認遮罩與數值；MRN 不可進研究封包。舊完整研究保存不可受此兩圖限制影響。
5. 母庫回收需保留私有模型／資料及專用 CI，不可把母庫直接反向合入公開庫。WoundAI3D 獨立未提交研究工具需由該工作流覆核，不能宣稱全面整合。

已嘗試透過本機 Claude Code 提交只含程式碼的覆核包，但收到 `401 OAuth access token is invalid`。尚無 Claude 覆核結論，不得標記已複核。
