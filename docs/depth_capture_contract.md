# 深度擷取契約（WoundAI3D 預留）

> **現在不會有值。** 這份文件定義的是欄位與格式，不是已實作的功能。
> 目的是讓 3D 上線時不必改契約，而不是讓現在的資料變得可用。

---

## 為什麼現在就定，而不是等 3D 開發時再說

**深度必須與 RGB 同一瞬間擷取才有意義。** 事後補不回來——不是「麻煩」，
是物理上不可能：傷口已經變了、病患已經出院、光線與角度都不同。

而定義幾個欄位的成本是零；日後改契約則要同時動 **App、後端、匯出腳本、訓練程式**四處，
還要處理「舊紀錄沒有這些欄位」的相容性。這與 `versionCode`、DB v5 的組織欄位是同一類決定：
**現在做很便宜，晚做很貴，不做則永久失去。**

⚠ 但要說清楚：**埋欄位不等於資料會自己出現。** 目前 App 沒有擷取深度，
所以 n=20 這批收案**不會**有深度資料。這裡只是讓未來不必改契約，
並讓現在的紀錄明確標記 `depth_source: "none"`，而不是含糊的「沒這個欄位」——
後者在日後分析時分不出「沒拍」與「拍了但沒存」。

## 欄位

隨 `POST /api/v1/annotation` 一起送，已加入 `PROVENANCE` 白名單。

| 欄位 | 型別 | 說明 |
|---|---|---|
| `depth_source` | str | `none` / `arcore_depth` / `lidar` / `stereo` / `photogrammetry` |
| `depth_map_key` | str | 深度圖物件鍵 |
| `depth_format` | str | `png16_mm`（建議）/ `raw_f32_m` |
| `depth_conf_key` | str | 置信度圖物件鍵 |
| `camera_intrinsics` | obj | `{fx, fy, cx, cy}`（像素） |
| `camera_pose` | list | 4×4 row-major |
| `depth_scale` | float | 深度值 → 公尺的乘數 |
| `capture_device` | str | 機型／感測器 |

### `png16_mm` 是建議格式

16-bit 灰階 PNG，值＝**毫米**，`0` 保留給無效值。

- **無損**：與組織遮罩同一個理由。深度內插出來的中間值代表一個不存在的表面點，
  而那正好落在傷口邊緣——量測誤差最大的地方。
- **範圍夠**：65535 mm ＝ 65 公尺，臨床攝距（20–60 cm）綽綽有餘，解析度 1 mm。
- **通用**：OpenCV、PIL、Android 都直接讀得動，不需要自訂解碼器。

`raw_f32_m` 保留給需要次毫米精度的場合（LiDAR 原始輸出），代價是體積大 2 倍且不可預覽。

### ⚠ `camera_intrinsics` 沒有它，深度圖沒有用

深度值只說「這個像素有多遠」。要換成公制座標必須反投影：

```
X = (u - cx) * Z / fx
Y = (v - cy) * Z / fy
```

沒有 `fx, fy, cx, cy` 就做不了這件事，而那些值**因機型、鏡頭、甚至變焦倍率而異**，
事後查不到。這是最容易漏掉、漏掉之後整批資料報廢的一個欄位。

### ⚠ `depth_conf_key` 不是可有可無

ARCore Depth 與 LiDAR 都會在邊緣、反光面、深色區域給出**看起來合理但完全錯誤**的深度值。
沒有置信度圖就無法把那些像素排除，而傷口的邊緣與潮濕反光處**正好**是這兩種情況。

又是那個熟悉的形狀：數值存在、格式正確、結果是錯的。

## 與現行 2D 量測的關係

memory 記載的既有驗證結果：

- **2D 比例法最穩**（方形 20 mm 誤差約 3.3%）
- **M3 反投影三角化表面積已驗證**（斜面 1.969 ≈ 2.0）
- 既有 iOS 模組是 stub，所以先前測試失敗

所以 3D 的定位是**補充**而非取代：

| 量測 | 現行 2D（ArUco 比例法） | 3D 能多做什麼 |
|---|---|---|
| 投影面積 | ✅ 已驗證 | 無明顯優勢 |
| **真實表面積**（斜面／曲面） | ❌ 低估 | ✅ 反投影三角化 |
| **深度／體積** | ❌ 做不到 | ✅ 潛行深度、傷口容積 |
| 潛行與隧道 | ❌ | 需要多視角，仍難 |

⚠ **ArUco 貼紙在 3D 之後仍然需要。** 深度感測器有自己的尺度誤差與漂移，
而貼紙是一個已知邊長的實體基準——它是驗證深度尺度對不對的唯一手段。
不要因為「有 LiDAR 了」就把貼紙拿掉。

## 待 3D 開發時才做的事

1. **App**：ARCore Depth API（Android）／ARKit Scene Depth（iOS）擷取與落盤
2. **後端**：`depth_map_key` 的接收與儲存（沿用 `tissue_mask_png` 的模式）
3. **品質指標**：深度有效像素比、置信度分布、與 ArUco 尺度的一致性檢查
4. **量測**：反投影三角化表面積（M3 已驗證的演算法）
5. **UI**：深度圖層與可信度視覺化（同樣要能關掉）

## 現在就該做的一件小事

App 送標註時帶上 `depth_source: "none"` 與 `capture_device`。
`capture_device` 現在就有值，而且它日後是分析「跨裝置差異」的唯一依據——
若某個機型的面積系統性偏高，沒有這個欄位就查不出來。
