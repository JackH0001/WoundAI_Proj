# 首次本人帳號核對：本機候選驗收

## 修正前後

本人候選服務原先同時要求安裝摘要及 Apple 服務帳號摘要；第一次登入前卻還沒有
服務帳號收據。不能用未核對的摘要解除這個相依問題，也不能因此先向一般帳號
開放服務。本輪新增明確限時、單一安裝的 `owner-review` 階段，普通部署預設不啟用。

| 階段 | 新行為 | 不會發生的業務動作 |
| --- | --- | --- |
| 初次核對 | App Attest 核對安裝，Apple 公鑰核對 ID token、nonce、audience、issuer、期限及 state，保存不可覆寫摘要 | 不交換授權碼、不保管 Apple refresh token、不建立帳號／session、不開額度 |
| App 顯示等待 | 202 必須綁定原操作；先保存 `owner_review`、清除該次 Apple 憑證 | 不自行重送授權碼、不購買、不辨識 |
| 操作員私有讀回 | 核對摘要、當前 challenge、原設定及期限；沒有對外讀回 API | 摘要本身不能啟用服務 |
| 明確切換 | 固定帳號摘要、完成額度與服務發布，改為 `owner-only`；本人重新按登入 | 不接受原核對期間的舊授權碼代替新的登入 |

## 首次初始化與回復順序

1. 固定來源、依賴、本人安裝摘要與未來最多一小時的期限。取得部署、精確權限及
   真正材料匯入授權後，才可操作真實環境。本輪只有本機合成驗收。
2. 私有初始化先執行 `subscription` 步驟，建立目前政策定義。實際 native 組合入口
   需要這份定義才能啟動；不能把「完全空白狀態可啟動」當成既成事實。此步不發布
   個人服務，也不初始化使用者額度。
3. 以 `LITE_INTERNAL_OWNER_MODE=owner-review`、本人安裝 SHA-256、
   `LITE_INTERNAL_REVIEW_UNTIL=<UTC epoch>` 啟動候選；不設定帳號摘要。
   必須保持原來的 App Attest、Apple 公鑰、請求預算及既有權利核對。
   只用於尚未開放一般使用者的候選服務；到期後新 instance 會拒絕啟動，不能把
   此短期修訂留作正式服務的長期入口。部署方案須明訂期限前的關閉／切換步驟。
4. 本人一次 Apple 登入只提交身分證據。私有管理面使用
   `AccountIdentityBridge.read_owner_review(installation, operation, until=...)`
   讀回；雜湊、期限、當前 challenge 任一不符即停止。這是受限元件，尚非正式
   雲端操作員執行器；禁止用任意物件下載或公開 API 代替。
5. 經核對後，在原初始化同一 UTC 日完成 `quota`、`release`。再以
   `owner-only` 和核對的帳號摘要部署；移除 review 期限。兩個限制都要讀回。
   此時本人另按一次登入，取得新的 challenge、ID token 與授權碼。
6. 失敗或超時保持新工作關閉；不退回無本人限制的部署、不清空舊帳號或稽核。
   保留既有參與者讀取舊結果、原帳號重新登入及刪帳權利。需要新期限或新修訂時
   固定新方案，不在背景自動延長。跨 UTC 日需依初始化工具的既定續接程序另驗收。

## 稽核與隱私

提案只含設定／安裝／帳號／challenge／ID token 雜湊、操作 ID 與期限；不保存
Apple subject、email、原始 ID token 或授權碼。回應不提供帳號摘要。
Apple token 驗證會使用既有公鑰流程，真實環境可能讀取 Apple 公鑰；測試使用
合成金鑰與本機簽章，不是真實 Apple 登入驗收。安全計數及防濫用計數仍會更新。

提案重播不重複寫入；另一個 Apple 身分不能替換同一操作。登出、換 challenge、
設定變更或 review 到期後，私有讀回拒絕使用舊證據。已通過驗證的證據可在原
一小時窗口內讀回，即使五分鐘登入 challenge 後來過期；真正啟用仍需新登入。
核對用 challenge 發出前會先耐久記錄用途；即使 202 回覆遺失或新修訂已啟用，
伺服器仍拒絕把這筆舊操作用來交換授權碼，回傳既有的明確重新登入協定。
新 App 可清除舊憑證並提示重新登入，不在背景自動取得新 Apple 授權。

## 本人核對的私有讀回（2026-11-18，本機合成驗收）

操作員使用 `tools/lite_owner_review_reader.py` 的 `prepare` 確認名單，再由
`observe` 以另外提供的唯讀 client 取得結果。本人安裝、單次登入操作、核對期限、
候選服務的設定檔指紋、專案編號、來源與映像均由事前檢閱的計畫固定。
安裝與操作需透過已核對的私有管道交給操作員。

三個儲存區前綴各有指定用途。讀回只需要設定、目前登入狀態、本人提案、核對標記、
裝置登記五個物件。套用到 GCS 時，由 IAM 另行限定物件名稱及唯讀權限。
兩次觀察同時核對內容與版本，登記尚未建立時必須得到明確的缺件回應。
若期間發生登出、登記、同內容換版、儲存服務拒絕讀取、逾時或時鐘倒退，操作員應重新核對。

回執包含計畫及帳號摘要、觀察到的物件版本與短效期限。到期時間取本次開始後 60 秒與原核對期限的較早者。
跨物件讀取無法鎖住後續變更，正式切換前需要再次核對並取得該次切換授權。對外 App 僅取得原有等待提示。
本機使用合成 Apple 登入及記憶體 GCS 替身。正式的執行身分、權限、私有交付管道及雲端驗收仍待接線。

本機操作員入口已接上 Google Storage SDK，合成回應通過後的實機驗收方式見[操作員離線規劃與私有讀回](lite_owner_review_command_20261118.md)。
