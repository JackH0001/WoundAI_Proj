# 首次使用教學（tutorial）規格

> 狀態：**規格，尚未實作。** 這份文件定義流程、每一步的文案與驗收條件。
> 實作涉及新畫面與一個跨畫面的狀態機，值得單獨一輪做好。

---

## 為什麼需要它

臨床人員第一次拿到這個 App 時面對的不是「一個拍照工具」，而是一條有**四道閘門**的流程：

1. 沒有①照護同意 → 量測按鈕是灰的
2. 沒有輸入滲液 → 修邊與存檔都按不下去
3. 沒有完成修邊 → 送不出訓練標註
4. 沒有②訓練同意 → 一樣送不出

每一道閘門都有畫面上的說明，但那些說明是**在你撞上它的時候**才出現的。
新使用者的體驗因此是「按了一個灰色按鈕、讀一段字、回上一頁、再回來」——
重複四次之後，他對這個 App 的印象已經定型了。

手冊解決不了這件事：**人不會在操作前讀手冊，只會在卡住之後讀。**
而卡住的當下他要的是「現在該按哪裡」，不是「這個設計的理由」。

---

## ⚠ 最重要的設計約束：教學不可以污染任何真實資料

這條排在所有 UX 考量之前。一個會產生副作用的教學，比沒有教學糟得多——
它會在臨床收案進度、癒合趨勢、訓練佇列裡留下永久的假資料，而那些資料
**看起來與真的一模一樣**。

具體要防的四件事：

| 風險 | 防護 |
|---|---|
| 建到假病患 | 教學用的病患固定為 `__TUTORIAL__`，`isTutorial=true`，不出現在病患列表 |
| 假紀錄進臨床收案數 | `source` 強制為 `sample`，且教學全程**不呼叫後端 classify** |
| 假標註進訓練佇列 | 送出標註那一步是**模擬的**，不打網路 |
| 假資料留在時間軸 | 教學結束時整批刪除；中途離開也刪 |

### 為什麼「不打後端」而不是「打後端但標記為教學」

標記能被忽略、能被漏掉、能在下一次改欄位時失效。**不送出的東西不會出錯。**
教學要教的是「按鈕在哪、順序是什麼、每一步在做什麼」，那些完全不需要真的送出。

代價是教學無法驗證後端連線。所以第 0 步保留一個**真實**的連線測試
（那是唯讀的 `/api/health`，沒有副作用），並在教學結束時告訴使用者
「剛才那一輪是模擬的，真實個案請從主畫面『個案』進入」。

## 觸發時機

- 首次啟動且尚未完成過教學 → 主畫面自動彈出詢問（**不強制**，可以「稍後再說」）
- 主畫面「使用說明書」頁面頂端常駐一個「重新播放教學」入口
- 帳號角色變更後不重播——教學內容依角色分支，但重複強制會惹人厭

`SharedPreferences` 記 `tutorial_done_v1`（帶版本號：日後流程大改時可以重播一次）。

---

## 流程（醫師版．完整 9 步）

每一步一張半透明遮罩 + 高亮目標控制項 + 一段文案 + 「下一步」。
**使用者必須真的按到那個控制項才會前進**，不是單純點「下一步」——
看過的東西記不住，做過的才會。

| # | 高亮目標 | 文案（一句，不超過 40 字） | 前進條件 |
|---|---|---|---|
| 0 | 設定頁「連線測試」 | 先確認連得到後端。這一步是真的，其餘都是模擬。 | 測試回傳成功或失敗皆可前進 |
| 1 | 主畫面「個案」 | 臨床量測一律從這裡進入，紀錄才歸得了戶。 | 進入個案頁 |
| 2 | 「簽署同意書」 | ①照護同意是必填，沒有它量不了。②訓練同意可隨時撤回。 | 完成簽署（教學用假簽名） |
| 3 | 「＋新增個案傷口」 | 一個傷口一組 WD- 代碼，回診請沿用同一個。 | 建立教學傷口 |
| 4 | 「開始量測」→「檔案」 | 用內建的教學圖，不會用到相機。 | 載入教學圖 |
| 5 | 滲液 0–3 | 滲液是 PUSH 分數的一部分，不填後面按不下去。 | 選任一值 |
| 6 | 「醫師確認・修邊」 | AI 的輪廓幾乎都要修。你畫的就是模型之後會學的。 | 進入修邊畫面 |
| 7 | 修邊畫面（子流程，見下） | — | 按下「完成修邊」 |
| 8 | 「醫師確認・送出標註」 | 送出的只有代碼與影像，姓名與病歷號永遠不離開手機。 | 按下（**模擬送出**） |

### 第 7 步的子流程（修邊畫面內，4 步）

| # | 高亮 | 文案 | 前進條件 |
|---|---|---|---|
| 7a | 「邊界＋」 | 沿著傷口邊緣塗，把 AI 漏掉的補進來。 | 有筆畫 |
| 7b | 「組織🖌」→「肉芽」 | 選好類別再塗。只會改傷口範圍內的像素。 | 有筆畫 |
| 7c | 「按住看原圖」 | 按住看原始照片，放開就回來。按住時畫不上去。 | 按住超過 0.5 秒 |
| 7d | 「完成修邊」 | 按取消的話這些都不算數，也送不出訓練標註。 | 按下 |

### 其他角色的分支

| 角色 | 差異 |
|---|---|
| 護理師 | 第 6 步文案改為「你也可以修邊，但不會產生『醫師已驗證』」；**跳過第 8 步**，改為一頁說明「送訓練標註須由醫師完成」 |
| 助理 | 跳過第 2、3 步（無 `patient.manage`）；第 6 步後結束，說明「請由護理師或醫師接手存檔」 |
| 工程師／管理者 | 完全不同的教學：設定 → 主控台 → 系統狀態三個紅燈的意義。**不走臨床流程**（他們沒有臨床權限） |

## 教學資料的建立與清除

```
進入教學
  ├─ 建立 Patient(name="教學示範", mrn="__TUTORIAL__", isTutorial=true)
  ├─ 建立 WoundCase(wdCode="WD-TUTORIAL", isTutorial=true)
  └─ 載入 assets/tutorial_wound.jpg

離開教學（完成 / 中途退出 / App 被砍掉後重啟）
  └─ deleteTutorialData()：依 isTutorial 旗標整批刪除
```

**用旗標而非代碼字串比對。** 比對 `wdCode == "WD-TUTORIAL"` 的話，
只要有人手動改了那個字串，教學資料就永遠留在資料庫裡並開始計入統計。
旗標是欄位層級的，改不掉也漏不掉。

**啟動時無條件跑一次 `deleteTutorialData()`。** 使用者在教學中途直接把 App 滑掉時，
清除邏輯不會執行；下次啟動補做，資料庫才不會慢慢累積教學殘留。

### 需要的資料庫變更

`PatientEntity` 與 `WoundCaseEntity` 各加 `isTutorial: Boolean = false`（DB v7 migration）。
所有查詢病患／個案的 DAO 一律加 `WHERE isTutorial = 0`——
**漏掉任何一處，教學病患就會出現在真實的病患列表裡**。

## 驗收條件

實作完成後，下列每一項都要能重現：

1. 走完整個教學 → 病患列表沒有多出任何一位
2. 走完整個教學 → 個案時間軸沒有多出任何一筆
3. 走完整個教學 → 主控台「我的送件」沒有多出任何一列
4. 走完整個教學 → 後端 `by_source.clinical` 數字不變
5. 教學進行到一半把 App 滑掉 → 重新開啟後教學資料已清除
6. 以護理師帳號跑教學 → 不會出現第 8 步
7. 以助理帳號跑教學 → 不會出現第 2、3 步
8. 教學全程**沒有任何 `/api/v1/classify` 或 `/api/v1/annotation` 請求**
   （用 `read_network_requests` 或後端稽核軌跡驗證：稽核裡不該有教學期間的紀錄）
9. 第 0 步的連線測試是**真的**打了 `/api/health`

第 8 項與第 4 項是這份規格的核心，測試要能自動化。

---

## 不做的事

- **不做強制教學。** 有經驗的使用者被強制走一遍會很反感，而反感會轉移到整個系統上。
- **不做「稍後提醒」的重複打擾。** 問過一次，之後只留說明書裡的入口。
- **不在教學裡教臨床判斷。** 「什麼是肉芽」不是這個 App 該教的，那是臨床訓練的事。
  教學只教操作：按鈕在哪、順序是什麼、哪一步不可逆。

## 與使用說明書的分工

| | 使用說明書（已完成） | 教學（本規格） |
|---|---|---|
| 形式 | `assets/manual.html`，主畫面第五個入口 | 覆蓋在真實畫面上的引導 |
| 時機 | 卡住時查閱 | 第一次使用時 |
| 內容 | 完整、可搜尋、依角色分頁 | 只有主線，一次一步 |
| 更新成本 | 改 HTML，隨 APK 出版 | 改狀態機，要重測 |

兩者都需要。手冊回答「為什麼」，教學回答「現在按哪裡」。
