# 醫療版傷口選單、分類與評估資料改版提案

日期：2026-10-16。狀態：供臨床與工程覆核的規格，尚未啟用新欄位或新量表。核對來源：公開庫 `1f3567019458dfa958a6564f809a6ccf402b035a`。

## 已確認的產品原則

一般病例以標準選單完成部位、位置與傷口屬性；補充文字只供特殊案件／特殊狀況。選單應涵蓋大部分傷口，不把「其他」當成正常工作流。保留「尚未判定」與「未評估」，不強迫猜測。iOS、Android 與後台使用同一份有版本的代碼表；民眾版沿用較簡單的選項，醫療版增加臨床細節。

先由醫師確認傷口屬性，再列出適用分類／量表。可由已確認數據計算的部分自動填入，其餘顯示待補項目。影像辨識不單獨決定病因、感染、缺血、神經病變或壓力性損傷分期。分類、嚴重度與癒合追蹤分開顯示。

## 現況核對

| 模組 | 現有設計 | 改版需求 |
|---|---|---|
| iOS CaseAndConsentViews／Entities／CaseRepository | `bodySite`、`woundType` 文字欄位 | 選單代碼＋顯示文字；保留舊資料 |
| Android CaseSelectScreen／WoundCaseEntity | 部位、類型自由輸入 | 同一份代碼表與條件選單，Room 遷移 |
| iOS WoundLite/LiteWoundLocation.swift、Backend/Flask/api_lite.py | 固定部位與左右側代碼 | 作為粗粒度共同對照，不直接塞入醫療版所有欄位 |
| iOS WoundPipeline／跨平台金標 | 以遮罩面積、組織比例門檻算現有 PUSH 衍生數值 | 與標準量表逐項核對，歷史算法標版本 |
| MeasurementEntity 等量測欄位 | 部分 `woundType`／標籤記錄 AI route | 不可直接拿來當傷口成因；分開命名與遷移 |

因此不只是把文字框換成下拉選單，也要增加結構化儲存、評估版本與送件快照。現有跨平台金標通過代表算法一致，不代表量表臨床效度成立。

## 建議介面

1. **新增傷口**：身體區域 → 詳細部位 → 左右側／表面 → 傷口成因。常用部位可置頂；提供選單搜尋，但搜尋文字不直接成為病歷值。每一傷口保留獨立 ID；同一部位有兩個傷口也不合併。
2. **傷口細節**：部位摘要、起始日期／不確定、主要成因、共存因素、目前評估。僅選「其他」時要求具體補充；其他病例可展開特殊狀況備註，平時收合。
3. **本次量測與評估**：保留現有影像、輪廓／組織修邊；顯示適用分類卡、各項輸入、資料來源及缺項。護理／醫師可操作範圍依既有角色規則。
4. **確認與送出**：一次確認本次評估、影像、遮罩、尺度與量表；建立不可變送件版本，雲端保存與 image／overlay 輸出使用同一份版本。輸出重試不重新上傳；分類／量表更正另建評估版本，不覆寫舊修訂。

例：右側 → 足部 → 足跟 → 足底面；成因「壓力性損傷」；共存因素「糖尿病」。系統不能因此自動改成糖尿病足潰瘍。另一例為小腿內側靜脈性潰瘍，出現靜脈相關評估，而不硬套糖尿病足分數。

## 部位選單範圍（初版候選，須臨床覆核）

| 區域 | 詳細選項與延伸 |
|---|---|
| 頭頸 | 頭皮、額、顳、枕、臉頰、鼻、耳、下頷、頸前／後；黏膜部位獨立標示 |
| 軀幹 | 胸、乳房／乳下、腹、背上／下、肩胛、脊柱、薦、尾、臀、坐骨、髖／大轉子、鼠蹊、會陰、生殖器 |
| 上肢 | 肩、上臂、肘、前臂、腕、手背、手掌、手指 1–5、指間、指尖 |
| 下肢 | 大腿、膝前／後、小腿前／後／內／外、內踝／外踝、足背、足底、足跟、前足／中足／後足、足趾 1–5、趾間／趾尖 |
| 其他／跨區 | 其他解剖部位＋補充；跨區保留主要部位及其他受累部位，不用「其他」取代所有跨區情況 |

左右側提供左、右、中線、不適用、尚未判定；中線與不適用不混為一值。表面選項依部位顯示：前／後／內／外、掌／背、足底／足背。部位已帶表面資訊時不重複詢問。手指／足趾序號只出現在相應部位，足跟不得搭配手掌面。雙側傷口一般拆成兩個傷口 ID。

代碼採穩定英文 key，繁中為顯示字典；新語言不改代碼。詳細足部代碼須能明確映射前／中／後足；資料不足時要求確認，不能從「足底」猜出前足。與 Lite 對照另存 mapping version，向粗分類映射可有資訊損失，反向不可自動補猜。

## 傷口屬性

主要成因單選：壓力性、糖尿病相關足部潰瘍、靜脈性、動脈／缺血性、混合血管性、外傷、手術／裂開、皮膚撕裂、燒燙傷、濕氣相關皮膚損傷、發炎／血管炎、自體免疫相關、腫瘤相關、放射線相關、其他、尚未判定。

共存因素可複選：糖尿病、神經病變、動脈循環不良、靜脈功能問題、壓力／剪力、醫療器材相關、潮濕／失禁等。這是醫師確認的記錄，不由選單推導診斷；例如醫材壓傷仍需確認壓力性分類。急慢性／病程、復發、感染評估、滲液、疼痛、周邊皮膚、潛行／竇道另外保存，不能混入主要成因選單。

## 分類與量表策略

| 適用範圍 | 建議顯示 | 可自動完成／仍須臨床輸入 |
|---|---|---|
| 壓力性損傷 | 分期；癒合追蹤候選 PUSH | 分期由臨床確認；PUSH 需按原工具定義取得面積指標、滲液與組織類別，不能把任意遮罩比例視為完整判定 |
| 糖尿病相關足部潰瘍 | 優先 SINBAD；感染評估 IWGDF/IDSA；專科條件具備時 WIfI | 系統整理部位與已確認面積；缺血、感覺、感染、深度等需檢查／確認。WIfI 所需生理量測缺少時不產生完整結果 |
| 靜脈相關 | CEAP；後續評估 VCSS 模組 | CEAP 是分類，不能把字母階段當加總分數；部分評估屬腿／病人層級，需獨立關聯 |
| 皮膚撕裂 | ISTAP 分類候選 | 皮瓣狀態由臨床確認；與慢性傷口癒合量表分開 |
| 其他、混合／未判定 | 通用量測與臨床描述 | 不為了填滿結果卡而硬套總分；專科量表以後逐項加入 |

IWGDF 建議依使用目的選擇分類；SINBAD 可供溝通與群體稽核，不能把分類分數直接轉為個別病人的預後承諾。[IWGDF 2023](https://iwgdfguidelines.org/classification-2023/)。感染判定需要局部或全身臨床徵象，不能只靠照片或組織顏色。[IWGDF/IDSA](https://www.idsociety.org/practice-guideline/diabetic-foot-infections/)。CEAP 使用有版本的分類規格。[2020 CEAP 共識](https://pubmed.ncbi.nlm.nih.gov/32113854/)。皮膚撕裂模組需再依 [ISTAP 官方資源](https://www.skintears.org/resources) 確定採用版本。

**PUSH 現況須先補核：**目前程式以分割面積及 5% 組織存在門檻產生數值，與標準工具的輸入定義不能視為等同。歷史資料保持原值與算法版本，介面應區分「既有衍生分數」與通過定義核對的新量表。先完成標準定義、使用許可及金標案例覆核才啟用；不可為了對齊而把所有傷口自動標成標準 PUSH。[NPIAP PUSH 工具與使用資訊](https://learn.npiap.com/products/push-tool-1)。Braden 是病人層級風險評估，不是某張傷口的嚴重度分數。

## 資料模型建議

以下為新契約草案，不表示目前 API 已支援。

| 資料層級 | 建議欄位 |
|---|---|
| 傷口識別 | `wound_id`、`patient_id`、`institution_id`；一傷口一 ID |
| 傷口部位／屬性版本 | `profile_revision_id`、`body_region_code`、`site_code`、`laterality_code`、`surface_code`、`digit_code`、`additional_sites`、`etiology_code`、`contributing_factor_codes`、`taxonomy_version`、`confirmed_by`、`confirmed_at` |
| 特殊補充 | `other_site_text`、`other_etiology_text`、`special_case_note`；長度限制、可空；不作為自動計分輸入 |
| 本次臨床評估 | `assessment_id`、`assessment_revision_id`、`measurement_id`、`profile_revision_id`、`assessed_at`、`actor_role`、`inputs`、`input_provenance`、`status` |
| 分類／計分 | `instrument_code`、`instrument_version`、`scope`、`applicability`、`missing_fields`、`subscores`、`total`、`rule_version`、`confirmed_at` |
| 修訂送件快照 | `annotation_revision_id`、`assessment_revision_id`、影像／輪廓／組織／深度資產參照及雜湊、計算來源、保存收據、輸出版本 |

部位與成因也可能被更正，因此保留歷史 profile 版本，不能讀目前傷口主檔來重新解釋舊分數。評估可有傷口、腿、病人三種 scope，禁止將病人分數複製成每個傷口的獨立結果。

面積至少區分 `segmented_area_cm2`、`length_width_area_cm2` 與 3D 表面積，保留量測方法、尺度來源與有效性。標準量表必須指定採用哪個欄位；未校正、LiDAR 質量未通過時不得用不可靠數值填分數。未知為 null，與真實 0 分、未評估、不適用分開。UI 可以呈現已知分項，但不得把部分和顯示成完整總分。

App 本地 SQLite／Room 新增欄位／評估表與 schema migration；後端接收、驗證、保存、查詢及研究匯出使用一致版本。後端重算可重算的分數，拒絕錯誤單位／不適用組合；臨床輸入保留操作者及原值。院內身份與自由文字仍按原資料分界處理，研究封包不因本改版自動加入病例號或自由備註。

## 相容與推出順序

1. 臨床覆核候選選單及各量表定義／使用許可；建立單一機器可讀字典與驗收金標。
2. 加入可空新欄位、雙讀相容、代碼校驗；舊 `bodySite`／`woundType` 原文保留為 legacy。不可用簡單關鍵字自動確診；下次編輯時提供選單確認，不要求一次搬移全部歷史。
3. iOS／Android 同時導入選單與傷口細節，後台同步顯示。新舊 API 能力協商；舊服務不支援時不能靜默丟棄欄位並顯示保存成功。
4. 先啟用結構化記錄與完整度提示；通過逐量表測試及臨床覆核後才啟用該量表計算，不一次放行所有分類。
5. 合成案例 → 兩端實機 → 保存收據／雲端讀回／研究匯出／兩張本地影像核對 → 測試群組更新。這次提案不更動現有來源分級政策，不刪除舊資料。

## 必須通過的驗收

- 常見部位與各主要成因均可不用自由輸入完成；由臨床團隊準備代表性案例，記錄「其他」使用原因再補足選單，不能先宣稱已覆蓋固定百分比。
- 左右／中線／不適用與部位不矛盾；指趾、內外踝、薦尾、足跟可精確選取；跨區與同部位多傷口不混淆。
- 每一選項 iOS／Android／後端代碼、顯示與合法組合一致；離線仍可操作。
- 未填不是 0；病因未判定時不套用專病量表；混合成因、糖尿病合併壓傷、未校正影像、缺乏深度均有案例。
- 量表每個界值、缺項、單位、異常值與版本均測試；預填值須顯示來源，臨床確認後才計分。
- 主檔更正不改寫舊評估；修邊、改尺度、組織更正、只改臨床評估，各自產生正確修訂與去重鍵；非相關量測不意外重算。
- 畫面、時間軸、研究送件與 overlay 的數字來自同一版本；本地重匯出不新增研究送件。
- 舊版升級、舊待傳工作、撤回同意、角色變更、跨 MMH／Demo 切換及後端版本不相容均保留安全邊界。

本提案不包含量表自動給治療建議。正式臨床啟用前，仍須與研究計畫／使用說明中的用途一致。
