# WoundAILite 個人服務首次啟用

若服務從沒有個人帳號、訂閱關聯與辨識額度，先前的遷移格式仍要求至少一筆舊用量。新服務用 `lite-usage-first-install/1` 明確描述首次啟用。原有 `lite-usage-cutover/1` 繼續要求核實的舊帳清冊及當日基準。

## 操作前提

1. 選定專屬環境，固定映像、來源、帳號與額度的命名範圍、底層儲存位置及版本。確認曾經提供相同權益的所有舊入口。把舊寫入停住，確認在途工作已排空，才能盤點。若曾有可轉移用量、帳號映射或購買關聯，使用既有遷移程序。
2. 保存一次完整、可覆核的凍結清冊。清冊應識別實際儲存位置、盤點時間、當日範圍、各來源的查核結果及寫入封鎖證據。不能用找不到某位使用者、一次列出空結果，或剛建立一個新桶來代替。舊來源遺漏或無法讀回時，維持封閉。
3. 僅在查證確實是首次啟用時使用空的 `baselines`。`baseline_sha256` 和 `account_map_sha256` 均為空清單按現有 `digest([])` 規則計算的摘要。`fresh_inventory_sha256` 是完整凍結清冊的摘要，並與訂閱首次啟用簽章中的 `inventory` 相同。兩邊的 `fence`、來源和映像都必須相符。
4. 操作端的觀察除了原有欄位，必須回傳同一份 `fresh_inventory_sha256`、`prior_quota_accounts=0`、`prior_account_mappings=0`。兩個數字指凍結時的歷史來源；開站後新增的正常帳號不應改寫它們。操作端必須有資格核對這些來源。App 與個人服務的執行身分沒有簽署或發布這份清冊的權限。
5. 在同一 UTC 日完成額度切換。操作員簽署啟用命令，獨立觀察者提供已排空的證據。核對啟用記錄及稽核後才允許首位使用者建立當日帳本。正常重送沿用原帳號及收據，跨日保留舊紀錄。若發現原本就有 v1 帳本，拒絕服務並保留紀錄供處理。

## 失敗回復

在發布前讀不到清冊、範圍不合或核對出舊用量，均不啟用。發布後觀察暫時不可得只回報；已核實矛盾則暫停新操作並保留帳本。經核准、修復並重驗後才能恢復。程式不會自動掃描正式資料或開通雲端服務。

可用 `test_lite_first_install_quota` 重跑合成測試。測試經候選 HTTP 服務的裝置登記、登入、辨識、重送、訂閱核對、暫停及重啟路徑，不需 Apple 私鑰或病患資料。
