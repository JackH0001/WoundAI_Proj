# WoundAILite local research withdrawal handoff

An account deletion can request research withdrawal. A consumer service App Attest installation and a research App Attest installation have different origins, counters and identifiers. The user explicitly confirms association of the existing registrations for this deletion. A matching hexadecimal ID, shared device, subscription, or Apple sign-in alone cannot authorize a research operation.

## From confirmation to receipt

1. The candidate account screen requires the accepted original deletion checkpoint and the corresponding research withdrawal request. The app can read its local progress without a network call. On explicit confirmation it saves the two origins, original service account, operation and current existing research installation before sending either request. If there is no readable research registration, the app asks the user to check the original installation and creates no new ID.
2. The personal service accepts only its own signed withdrawal-challenge request to `POST /api/v1/lite/account/deletion/research-offer`. It checks the original registered owner, accepted closure operation and immutable research-withdrawal confirmation. The first target of this operation is durable. Replays use the same signed pair and a fresh ten-minute ticket. A different target cannot replace it.
3. The independent research service accepts only its own signed withdrawal-challenge request to `POST /api/v1/lite/research/deletion-proof`. It checks both native signatures, scope, bucket, owner and ticket interval. It adds its own signature, durably saves the proof, and returns a receipt digest. An expired ticket with no prior acceptance needs a new offer; a previously accepted request can read the identical receipt. Neither request includes images, depth data, masks, a human login token or a new consent.
4. The phone records only validated progress for the same account, operation and origins. A receipt confirms both identities; it says nothing about media, backups or final account deletion. The private worker may use an explicitly reviewed manifest, or read the saved issuer records directly when its pinned configuration selects that source. The receipt is not a command to execute a cleanup. Other devices and historical subjects without proofs remain pending.

## Deployment boundary

Both routes default to unavailable. Each service must receive only its own read-only signing seed and the two pinned public keys. The mount bytes must match the SHA-256 pin, role, scope and destination. The native image only exposes the offer route; the research-only image can expose only the acceptance route. Do not embed private keys in the app or in source, send proofs to telemetry, or grant either service permission to run private cleanup. Provider-level signer custody, key rotation/retention, cloud readback under the deployed worker identity, Apple App Attest, and device acceptance remain separate release gates.

## Claude reproduction

Run `test_lite_research_issuer` and `test_lite_cross_origin_research` with the same local Python paths as the Lite prelaunch workflow. The fixture registers two independent synthetic attested clients, writes one synthetic image, submits an account closure and transports both signed HTTP requests. The private worker consumes the verified evidence, fences only the actual research registration and keeps the original media and its history intact. The tests also cover an expired first delivery, lost replies, different targets, wrong audience/owner, changed signatures and an incorrect challenge purpose. The iOS suite `LiteResearchDeletionLinkTests` exercises interrupted progress, explicit retry, immutable bindings, a different service account, missing research registration and rejection of a false cleanup claim.

The TestFlight archive and public PR at `fa827a5` predate this change.

## Private worker receipt source

Use `research_associations` with `native_key`, `research_key`, and `source: issuer-records/1` to enable direct readback. The existing `proofs` array remains supported for reviewed static fixtures. The two modes are mutually exclusive. Missing configuration leaves cross-service work pending. Use distinct public authorities, separate from operator/drain signers. The private worker image contains the verifier and reader but no issuing endpoints or private issuer keys.

In direct mode one resolution reads at most two exact state objects. On GCS each logical object read includes generation-pinned metadata and content. The first read uses the closure scope, account, native registration and original operation to find the immutable native offer in the existing deletion audit. The worker verifies its signature, account, operation, native registration proof and target bucket before using the proposed research identifier for the second read. The second read uses only the existing research-state namespace. Both signatures and the complete original packet must match. Missing evidence leaves a resumable pending cursor. Malformed evidence, conflicts and storage errors stop the operation. Receipt lookup does not list accounts, contact either origin, sign evidence or write to either evidence record. The worker applies ordinary command, provider-budget, frozen-inventory and audit controls. An unresolvable legacy grant remains visible as pending after the other verified grants close.

Run `test_lite_worker_research_records` for real signed HTTP handoff using synthetic roots, two exact-key reads, different targets, lost reads, package startup, and resuming a pending worker when the second issuer accepts. Before a candidate deployment, verify the pinned store prefixes, key custody and IAM; simulator and fixture results do not establish production authority or media destruction.

When the first pending grant lacks evidence and other frozen grants remain, the private worker alternates between the first pending grant and a bounded walk of the remaining frozen grants. Each call still attempts at most the configured number of grants. The first receipt of a newly verified device therefore can stop that device's research writes even if a newer device has not confirmed. A restart recovers the walk from a separate audited cursor. Only the ordinary ordered cursor counts completed grants; an early fence does not imply that the whole account was scanned or that any media was erased. Repeated sweeps reuse the same finite set of checkpoint audit identities per frozen plan.
