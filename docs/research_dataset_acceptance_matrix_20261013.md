# 研究資料完整性與用途驗收矩陣

2026-10-13 依使用者要求：平台核心目的為傷口與組織分割研究，以及後續 WoundAI3D 建模／訓練；「HTTP 成功」和「檔案存在」不足以宣告研究資料完整。本矩陣是實作與發布門檻，尚未全部接入線上統計或訓練匯出，不是已完成全面驗收的證明。

## 分別核對的用途

| 用途 | 必要資料與證據 | 不可替代的內容 |
|---|---|---|
| 傷口分割 | 正規化 RGB、影像雜湊與尺寸、最終傷口二值柵格、柵格至 RGB 轉換、修訂／來源／確認狀態 | 簡化輪廓不是原始逐像素遮罩；螢幕疊圖不是標籤 |
| 組織分割 | 上述影像關聯、無損類別 PNG、標籤字典與版本、ROI 轉換、醫師確認與修改狀態分開、每版保存 | 組織比例或「曾進入修邊」不等於逐像素精標 |
| 單視角 RGB-D 回放 | 同次影像與原始 Float32 深度、單位／長寬／步幅、內參與參考尺寸、方向沿革、採集識別／時間來源、原始位元與 metadata 雜湊、確切標註修訂連結 | PNG 毫米量化不能冒充原始深度；相同比例不能證明配準 |
| 多視角建模 | 單視角要求，加 session／視角序列／相機相對姿態／座標定義與其驗證證據 | 缺姿態不得補成單位矩陣或把獨立照片當已配準序列 |
| 模型迭代比較 | 原始模型候選與最終人工版分離、實際載入模型 artifact hash、前處理／融合描述、各路 execution／selected 狀態 | route 或檔名不能代替模型指紋；未執行模型不得補造候選 |
| 研究准入 | 當下有效同意／撤回、來源分層、核准範圍、人工品管及資料權限 | 技術完整性、醫師確認與 IRB／研究准入互不替代 |

原生信心與有效值遮罩必須分開。AVDepthData／現有採集路徑未提供的姿態、原生信心或曝光時間，保持 unavailable／unknown，不生成虛構欄位以湊齊格式。

## 本輪程式核對與缺口

- 已合入：不可覆寫標註資產、深度內容修訂、image＋annotation receipt 關聯、撤回拒收、IAP／角色隔離、CAS 帳號版本、工作階段重用與稽核效能修正。
- 本輪補修：醫療 sidecar v3 固定同次採集 UUID 與 callback wall-clock；Lite 新採集以 lite.rgbd/2 帶相同來源，v1 舊資料繼續照舊解析。不是精確 sensor exposure 時刻，也不能單凭它證明 RGB／深度同步。
- 本輪補修：醫療深度回執嚴格核對 image、完整 raw SHA、request metadata SHA、annotation revision、server canonical metadata／payload hash、depth receipt。保存後本機保留修訂與雜湊；本機回執寫入失敗保持待傳。
- **未完成：** 新後端 synthetic-review-validation profile、示範 UI 固定 context 全接線與跨環境背景工作驗收。
- **未完成：** 最終傷口原始二值柵格的明確上傳契約。兩端本機 EditRaster 有獨立 mask；目前 annotation 以 polygon／polygons 與組織 PNG 傳輸，組織 PNG 中未知類別可為0，不能保證以非零類別完全還原最終傷口 mask。
- **未完成：** student／AU 各路原始候選及模型 artifact 指紋完整保存。參照 WoundAI3D `UPSTREAM_MODEL_PROVENANCE_HANDOFF_20261007.md`，不得把候選／輪廓的存在誤當逐位元原始候選保存。
- **未完成：** 新版兩平台實機與雲端相同資料讀回驗收、不對稱實體標靶配準、多視角姿態／session，以及授權後的舊資料逐筆分類。這些不由本輪合成單元測試取代。
- Android 目前 MMH 路徑沒有實作原始深度採集；應明示 2D-only。其傷口／組織精標仍可有2D研究用途，不虛稱與 LiDAR 機型3D能力相同。
- WoundLite 的民眾圈選保持 lay label 與醫師精標分層；Lite 現有功能不能宣稱產生醫療版五類精標。

## 舊資料處置

先按記錄及修訂讀回資產、核對雜湊與同意，再分成2D用途可用、RGB-D結構待配準、缺漏隔離候選；每筆留下缺漏原因與來源版本。深度格式不足以作3D，不表示其2D精標一定無用。未知方向／時間不得猜補，不以今天重新序列化取代歷史證據。

「封存」在本方案指限制用途與保留可追溯來源，不代表永久保留或准許訓練。撤回與保存期限優先；本輪沒有搬移、刪除雲端物件，沒有修改 lifecycle，也沒有停用舊服務。

## 發布前必測

1. 新拍攝、相簿／無深度、同圖不改遮罩確認、改傷口邊界、只改組織、只改分數，各自產生正確來源與修訂。
2. 斷網、逾時、重啟、背景／前景、重送和重複點擊後，收據不錯配、不丟本機原始深度、不覆寫歷史版。
3. 每個資產改1位元、交換影像或標註修訂、缺／錯內參與方向、時間未知、PNG代替f32，都能拒絕相應用途。
4. 撤回後的新送件、待傳、讀取及研究匯出皆遵循最新狀態；先前保存成功不等於永久授權。
5. 用接收端 WoundAI3D 實際匯入同一完整封包，確認最終遮罩、類別字典、座標、尺度與深度一致，另驗證實拍精度與重複性。
6. 新環境通過上述驗收與 App 操作驗收後，才切換示範入口；舊資料封存／舊服務停止各自有明確清單，不能僅依環境年齡一刀切。
