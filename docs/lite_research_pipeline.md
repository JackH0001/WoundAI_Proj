# WoundLite 研究資料管線規劃（2026-08-19 起草）

回答三個問題：上傳的資料**在哪看**、**怎麼變成模型進步**、
**怎麼變成臨床可參考的研究結果**。

## 0. 現況與缺口

已落地：`lite/<anon_id>/<image_id>.{jpg,json,depth.png,conf.png}`＋
`lite_index.jsonl`（含 route/escalated——「哪些靠集成救回、哪些連集成都空手」
已可篩）。撤回通道已有。

三個缺口：

| # | 缺口 | 嚴重度 |
|---|---|---|
| 1 | **主控台看不到**——上傳成功與否、內容、統計全部只能翻 GCS | P0 |
| 2 | **手動圈選的輪廓沒有回傳**——民眾親手圈的邊界是弱標註 GT，目前整批漏收；辨識失敗的難例反而是最缺標註的 | P1 |
| 3 | meta 沒記 `consent_version`——日後研究使用要能回答「這筆是在哪一版同意文案下收的」 | P1 |

## 1. 可視性（P0，Windows/console）

主控台新增「民眾版資料」頁籤（權限 `flywheel.stats`）：

- 清單：時間、anon_id 前 8 碼、bytes、輪廓數、深度有無、route、
  escalated、face_reject／429 計數（後兩者從 rate/log 彙總）。
- 單筆預覽：影像＋輪廓 overlay＋深度快照（重用醫療版 preview.svg 路徑）。
- 統計卡：日上傳量、同意率、route 三桶占比（student 直取／集成救回／
  全空）、深度附帶率、平均量測值分佈。**route 三桶占比就是模型進步的
  即時儀表**——student 直取率上升＝蒸餾有效。

## 2. 治理前提（研究使用之前）

- `consent_version` 進 meta（後端一行）；iOS 同步在同意頁記版本字串。
- 保存期限政策寫明（建議與醫療版一致的分級：影像 N 年、幾何/統計永久）。
- 正式研究發表前送倫委會核備（自願提供之去識別資料次級使用）；
  App 端同意文案已涵蓋影像/深度/量測值，**回傳手動輪廓前要補一句**
  （見 §3，iOS 端改文案）。
- 紅線：**Lite 資料永不連結個人或病歷**。「病患自測回傳主治醫師」是
  另一個產品（需帳號與另一份同意），明確 out of scope。

## 3. 眾包弱標註回收（P1，兩端）

同意者按「存入紀錄」時，把**最終輪廓（手動或微調後）＋量測值＋來源標記**
回傳既有影像：

- 後端：`POST /api/v1/lite/annotation`（匿名、綁 image_id＋anon_id、
  只收 polygons/measured/source=manual|cloud_edited、限流同 segment）。
- iOS：存檔流程追加上傳（同意者、且該影像先前有上傳過才回傳）；
  同意文案補「您圈選的傷口範圍」一項。
- 資料分層使用：民眾輪廓＝**weak label**（半監督/預訓練用），
  醫師修邊＝gold（監督訓練）。兩層永不混標。

價值鏈：辨識失敗 → 民眾自己圈 → 回傳 → 正是「連集成都空手」那批
最缺標註的難例**自帶答案**。

## 4. 模型迭代閉環（P2–P3）

1. **難例采礦**：`lite_index` 的「全空」桶 → 標註隊列（醫師在 console/
   醫療版工具補 gold GT，source=lite_hard）。
2. **評測集凍結**：抽樣難例＋典型例凍結成 benchmark（版本化，不再變動）；
   之後每一版模型都跑同一份，才有可比的進步曲線。
3. **蒸餾**：student 以「A∪U 集成輸出＋民眾 weak label＋醫師 gold」
   半監督再訓練 → 上線後看儀表：escalate 率↓、全空率↓＝真進步。
4. **地端 WoundSegLite** 從同一管線蒸餾（驗收門檻已定於
   `WoundLite/Models/MODEL_SPEC.md`：mIoU≥0.85、<1s），落地即接上
   App 既有的「地端→雲端→手動」優先序與買斷商模。

## 4b. WoundAI3D 建模優化（使用者建議，2026-08-19 納入）

Lite 深度資料對 3D 建模的價值獨立於分割訓練——它是唯一能大量取得
**多機型×多距離×多角度×多光照** RGB-D 對的通道（醫療版收案量級做不到）：

1. **品質閘學習化**：現在的門檻（表面/投影比 1.25、攝距 22cm、覆蓋 0.7）
   全是實驗室手工值。以 lite 量測值＋深度統計訓練「深度可信度預測」，
   品質閘從硬閾值升級成學習型——誤擋率與漏放率都會降。
2. **平滑參數最佳化**：`smooth_depth` 的 8mm 物理尺度是 phantom 定的。
   用有貼紙 GT 的樣本（印刷樣例＋醫療對照組）對真實場景 grid-search
   per-condition 最佳平滑 → 回寫 `measure3d.py` 與 `DepthAreaEstimator`
   （兩端同步，PARITY 慣例）。
3. **體積基準面升級**：現在的環帶**平面**擬合在肢體曲面上系統性偏差。
   累積的傷口周邊皮膚幾何 → 學習肢體曲面先驗（柱面/樣條）→ 基準面從
   plane-fit 升級 curved-fit，直接提升容積與最深值的準度。
4. **濕亮面補洞**：LiDAR 對濕潤/反光面的深度洞，用 RGB＋周邊深度訓練
   inpainting → coverage 低的樣本從「警告」變「可救」。
5. **多視角底料**：同一 anon_id 對同一傷口的多次拍攝＝天然弱多視角對，
   是 P3（ARKit 多視角重建）的自監督一致性訓練資料——現在就開始累積，
   到時不用從零收。

## 5. 臨床可參考的研究產物（依可發表順序）

1. **誤差表 v2（真實場景）**：後端拿 lite 深度＋內參重算面積，與 App 端
   `measured` 交叉驗證 → 民眾實拍（光線差、手持晃動）下的誤差分佈。
   phantom 誤差表（實驗室）已有，v2 補上生態效度——臨床醫師看到病人
   自測數字時的**折算參考**（「居家自測 ±X%」）。
2. **拍攝品質分佈**：tilt/攝距/深度覆蓋的實際分佈 → 回饋取景指引與
   品質閘閾值（現在的 25°/22cm 是實驗室定的）。
3. **居家癒合軌跡統計**（累積量夠之後）：表面積週變化率的分佈 →
   「正常癒合帶」參考曲線 → 反哺 App 的紅旗規則（「連續兩週未縮小
   建議就醫」有據可依），並可作為臨床衛教素材。
4. 模型進步報告：route 三桶趨勢＋benchmark 曲線（工程產物，支撐 1–3）。
