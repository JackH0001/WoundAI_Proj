# Lite 相機與圈選工具列中英文驗證 — 2026-11-11

## 修正前後

相機及修正圈選是先前多語工作的剩餘入口。本輪增加30組配對顯示字串，以及
`InfoPlist.strings`的一組相機權限說明。Lite的首次圈選與歷史修訂兩處都傳入相同顯示介面。

| 原本 | 本輪 |
| --- | --- |
| 英文介面進相機／圈選後混用繁中 | 對焦、取消、圈選、擦除、移動、原圖、縮放、復原／重做與完成皆可英文顯示 |
| 無LiDAR仍寫「照片照常可量測」 | 明確指出無法提供免貼紙面積估算 |
| 硬體支援即顯示深度擷取中、供研究 | 只說硬體可用，是否取得可用深度須拍攝後核對，不代為同意研究 |
| 無相機錯誤指向Lite沒有的相簿／檔案入口 | 改請使用有相機的裝置；取消保留先前照片與圈選 |
| iOS相機權限說明只有繁中 | 增加英文，明確保留研究上傳須另同意 |

共用醫療相機預設顯示函式仍是identity；醫療修邊不套用Lite翻譯。相機CameraModel、
RasterState／EditCanvasModel與Lite量測VM／品質門檻三段程式逐byte未變。
本輪不調整相機格式、濾波、對焦、深度、遮罩運算、面積、修訂、同意或上傳。
錯誤只翻譯確定前綴，Apple原始錯誤細節原樣保留，含換行及百分號。

## 失敗證據與限制

首次QA入口用兩個Bool狀態開畫布，第一張空畫布誤帶入有輪廓資料，UI測試如實失敗。
只把測試入口改成有身分的空白／既有畫布選項，並將合成圖固定為1x像素，正式流程未變。

ImageRenderer無法呈現此Canvas與UIKit滑桿，會顯示不支援符號。該輸出只核對文字，
不能用來證明畫布效果；以最終實際模擬器UI截圖與手勢驗證為準。

第一次英文權限測試失敗：系統仍是繁中，App啟動語言不會改變SpringBoard權限對話框。
原始UI樹保留；改以英文系統驗收後通過，再恢復QA原繁中系統。翻譯資源本身未放寬。

本輪未驗證實機快門、深度準確度、訂閱購買、雲端上傳或真實刪帳；無網路推送、部署、IAM、
商店交付或資料清理。指南與其他市場核對仍未完成，不能稱完整全球上架已就緒。

## Claude覆核重點

1. 共用醫療預設與Lite覆寫是否只作用在文字；兩個Lite編輯入口是否均已接線。
2. 查三段byte核對及原圖／undo測試，確認未藉翻譯修改面積或遮罩。
3. UI產物必須包括真正空白、原圖、擦除、無相機錯誤及英文系統權限對話框。
4. 保留首次失敗，區分隔離QA、單元render、原生模擬器、實機與雲端證據。
