# Lite 中英文 PDF 與品質文字排版驗證 — 2026-11-10

這一批接續 `b506d40` 的服務介面翻譯，只處理單筆 PDF、同傷口時間軸 PDF 與匯出選項。
不是全 App 英文化，也不是新的面積精度、真實傷口或雲端驗收。原始資料、遮罩、深度、
帳號、研究同意、服務額度與稽核不做遷移或改寫；沒有部署或 Apple 交付。

## 修正前後

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 報告語言 | 報告及匯出選項固定繁中 | 依匯出時的介面語言選繁中／英文，136 組對照；其他語言仍以原繁中顯示 |
| 面積與品質 | 中文來源與警示 | 同樣的數值、品質門檻與圈選版本分流；英文區分 LiDAR 表面積、相機投影及貼紙校正 |
| 舊雲端圈選 | 已有可能偏小的中文提醒 | 英文保留「範圍與面積可能低估」；沒有因此替舊圈選背書 |
| 固定文字框 | 長文字可能超出框；時間軸只列首項品質提醒 | 量測文字高度；必要時加補充備註頁，保存其餘不同的品質提醒，保留照片框與細輪廓 |
| 歷史內容 | 原數值與使用者文字 | 只翻譯已知顯示字串與完整匹配的三種數字警示；自訂名稱／未知文字原樣保留，不回寫原紀錄 |
| 時間與分組 | 依同傷口及拍攝日期篩選 | 規則不變；介面語言不改日期區間、時區、傷口歸屬或數值；匯出開始時凍結語言 |

單筆報告原有的 700 字元防護保留；時間軸補充文字亦以 700 字元為上限，超過時明確
標示回 App 查看完整原文，並未截短保存的紀錄。這個上限不代表無限制逐字匯出。
附加備註頁採連續頁碼；照片索引仍指向原照片頁，不受其後新增備註影響。

## 本機測試與實際輸出

- 一般 Release 與本人候選 Release 各 **595 通過、0 失敗、1 既有略過**。
  兩種設定重複覆蓋，不可相加；本輪新增 7 個 XCTest 已包含其中。
- 略過的是模擬器無法提供檔案保護類別的既有測試，不表示實機保護已通過。
- 新案例涵蓋：136 組字串／參數一致、完整匹配才翻譯數字警示、原 JSON 不變、
  日期／分組／數值不變、英文趨勢與照片、長提醒與第二項提醒、品質拒絕時不輸出面積。
- 原有測試繼續驗證遮罩疊圖、原色、細輪廓、照片尺寸、來源分線、缺照片、
  日期不明、舊紀錄、來源變動與暫存分享檔清理。
- 由實際 XCTest／UIKit PDF renderer 輸出三份合成報告，共 6 頁：單筆 1 頁、
  兩筆時間軸 3 頁、長提醒 2 頁。以 Poppler 轉圖逐頁目視並獨立擷取文字核對。
  示例值為表面積 10.08／8.25 cm²、投影 9.91／8.10 cm²，並非實物精度證據。
- 首輪新測試有一項 PDF 文字比對失敗：英文部位分隔符被 PDF 擷取正規化。
  英文顯示改用逗號後重跑；繁中分隔符維持原樣。後續也整理單／複數共用的計數文字，
  最終兩種完整 Release 重新核對通過。首次失敗與後續成功紀錄均保留。

## Claude 重跑

覆核包提供固定來源、兩筆累計 patch、變更檔、XCTest summary/tree、完整文字日誌、
三份合成 PDF、逐頁圖、雜湊清單與驗證器。Windows 可重跑檔案／測試證據／字串表核對，
PDF 獨立內容核對需 `pypdf` 與 `pdfplumber`；Swift 執行仍需 Xcode。

一般設定在 `iOS` 執行 `xcodegen generate --spec project.yml`，候選設定使用
`project.lite-sandbox.yml`；兩者跑 `WoundLite` 的 Release test。
`tools/verify_xctest_results.py` 必須同時核對 summary 與完整 test tree，不能只看日誌尾端。

重點檔案：`LiteReportCopy.swift`、兩份 `LiteReport.strings`、`LitePDFReport.swift`、
`LiteTimelinePDF.swift`、`LiteHistoryView.swift`、`LitePDFReportTests.swift`。
