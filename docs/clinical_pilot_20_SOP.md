# 真實臨床照 n=20 飛輪端到端收案作業指引

> 目的：拿到 WoundAI **第一批真實臨床證據**。到目前為止所有精度數字都來自印刷模擬傷口與合成圖
> （演算法鏈 ±1.9%／App 全鏈 ±6%，見 `EVIDENCE_LEDGER`），**臨床影像上的表現尚無任何數字**。
> 本批的目標不是訓練出更好的模型，而是**證明資料鏈能在真人傷口上跑通，並取得第一組臨床基準**。

## 1. 收案條件

- **n = 20**，每張為不同傷口（同一傷口不同時間點另計，不算入 20）
- 組成建議（避免只收好拍的）：
  - 糖尿病足潰瘍 ≥ 6（主力適應症）
  - 壓瘡 ≥ 6（含薦骨/足跟等曲面）
  - 其他（燒燙傷／靜脈潰瘍／術後傷口）≤ 8
  - 面積分布：< 2 cm² 至少 4 張（**小傷口是已知短板**，周長占比大、描邊誤差被放大）
  - 難例刻意收：低對比、深色皮膚、滲液反光、多發破碎病灶各 ≥ 1
- 排除：影像含臉部或可識別特徵、貼紙未完整入鏡、明顯失焦

## 2. 拍攝協定（每張都照做）

1. 校正貼紙**貼在傷口正旁邊、與傷口同一平面**（不要貼在彎曲處或離很遠——尺度誤差來源）
2. 相機距離 20–30 cm，**盡量正拍**；已驗證斜角至 60° 無系統性劣化，但正拍仍最穩
3. 光源均勻，避免閃光直射造成滲液反光白斑
4. 每個傷口拍 **2 張**：一張正拍、一張約 30° 斜拍 → 用來看**同傷口重測差異**（重複性）
5. 拍完立即在 App 內量測，不要事後從相簿補（避免壓縮／裁切破壞尺度）

## 3. App 操作流程（每張）

```
個案管理 → 選病患 → 確認①照護同意✓ → 選該傷口個案（畫面上方會顯示 WD-code）
  ↓
選「後端」模式 → 載入照片 → 等 classify
  ├─ 確認結果卡顯示面積、路由（student 或 cloud_escalated(AU)）
  ├─ 進「醫師確認・修邊」→ 確認標題是 [尺度:ArUco✓]（若顯示 AI後備⚠ 表示沒偵到貼紙，重拍）
  ├─ 修邊：粗筆刷塗滿 → 細筆刷沿邊修
  │    心法：青線「中心」壓在傷口與皮膚交界，**不要把 1–2px 暗紅暈帶塗進去**（會系統性偏大）
  ├─ 輸入滲液 0–3（PUSH：0無/1少/2中/3大）
  ├─ **樣本來源選「臨床」**（必選，無預設）——選錯會讓收案進度失真：
  │    臨床＝真實病人；範例＝示範圖；模擬圖＝印刷驗證單。只有「臨床」計入 by_source.clinical
  └─ 送出訓練標註 → 應顯示「✅ 已送出,進再訓練佇列(WD-…)」
```

**AI 回空遮罩時**（分布外樣本）：直接從零手畫，面積仍準（ArUco 尺度與 AI 解耦）。
**同一張要重修**：再送一次會被判為「修訂版」，匯出時只取最新，不會產生矛盾 GT。

## 4. 每張要記錄的欄位（另建離線表，不進 App）

| 欄位 | 說明 |
|---|---|
| WD 代碼 | **個案的固定代碼**（建立個案時配發，回診沿用）。與紙本同意書編號對照，對照表離線保管 |
| 傷口類型 / 部位 | 糖尿病足、壓瘡…／足跟、薦骨… |
| 臨床參考量測 | 尺規最長徑 × 最寬徑（cm）——**這是唯一的外部對照**，務必量 |
| App 面積 | 修邊後顯示值 |
| 路由 | student / cloud_escalated(AU) |
| AI 初始是否可用 | 空遮罩／大幅低估／堪用 |
| 備註 | 反光、滲液多、深膚色等 |

> 尺規長 × 寬**不等於**真實面積（橢圓近似約 π/4×L×W ≈ 0.785 LW）。
> 它不是真值，只是**合理性上下界**——用來抓「差一個數量級」的錯誤，不要拿來算誤差百分比。

## 5. 收完之後要跑的驗證

```powershell
# 1. 佇列健康度（期望 by_source.clinical = 20）
curl -H "Authorization: Bearer <JWT>" "http://127.0.0.1:5000/api/v1/flywheel/stats?source=clinical"

# 2. 匯出訓練集（少於 20 會誠實中止，不硬訓）
python engineering/phase2/export_flywheel_dataset.py --source clinical --min-samples 20

# 3. 目視抽查遮罩是否貼齊
#    dataset_<日期>/masks/*.png 疊回 images/*.jpg
```

### 要產出的三個數字（進 EVIDENCE_LEDGER）

1. **臨床影像 AI 分割 Dice**：以醫師修邊 GT 為準，算 student 與 A∪U 各自的 Dice
   → 這是**第一次有臨床 GT**，先前 0.762 / 0.924 都是回溯資料集或 n≤5
2. **escalate 觸發率**：`cloud_escalated` 佔比。合理區間約 20–40%；
   >60% 表示 student 在臨床分布上太弱，<10% 表示判難門檻失效（`min_confidence=0.50` 待驗證項）
3. **同傷口重測差異**：正拍 vs 30° 斜拍兩張的面積差 → 重複性（目標 CV < 10%）

### 判定

- ✅ 資料鏈通過：20/20 進得了 `by_source.clinical`，匯出的 mask 目視貼齊
- ⚠ 若 `orphan_no_image` > 0 → App 未帶 image_id，回頭查前置檢核 #3
- ⚠ 若 `image_file_missing` > 0 → 後端 `flywheel/images/` 被清或跨機器，檢查部署

## 6. 這批**不能**用來做什麼（誠實邊界）

- **不足以重訓模型**（n=20 遠不夠）。用途是資料鏈驗證＋第一組臨床基準＋回歸集。
- GT 為**單一醫師描邊**，無跨評分者一致性（ICC）；App 全鏈含描邊誤差約 ±6%。
- 尺規對照非真值，**不可寫成「臨床面積誤差 x%」**。真正的面積臨床驗證需 phantom 或
  平面追描（描圖膜＋數化）作參考標準，列為後續。
- 不得宣稱「AI 診斷」——分類頭仍為規則式／heuristic（見 `MODEL_INVENTORY`）。
