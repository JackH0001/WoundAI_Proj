# 部署前來源清冊：唯讀 metadata 與未知狀態

本輪新增 `tools/lite_fresh_inventory.py`，不修改 App、後端服務或資料格式。它只接收已核對來源表及注入的 GET transport，沒有憑證探索、物件下載、部署、IAM、Secret、KMS、清理或寫入操作。

## 為何需要

首次初始化必須先區分「新個人服務帳本」與「舊研究服務的每安裝額度」。研究服務的成功辨識、嘗試與標註日誌已存在；不能把它們改成空資料，也不能把檔案數當成辨識次數。另一方面，找不到新桶，只能證明該次 GET 顯示不存在，不能單憑這點證明過去所有服務都未使用過。

此清冊是獨立的觀察工具，**永遠不產生 bootstrap 授權**，也不替代停用舊 writer、排空請求或人員覆核。

## 行為

- 來源表先核對摘要、明列 project number、bucket、prefix 與用途；至少覆蓋 accounts／links／quota，拒絕重複、重疊或不完整範圍。來源範圍的正確性仍要由部署覆核確認，不由工具自行猜測。
- 目錄前綴與舊式 `lite_rate_...jsonl` 檔名前綴分開指定，避免在檔名前綴後錯加 `/` 而漏查。
- metadata 只讀取名稱、generation、大小及刪除狀態；輸出不保留個別物件名稱，只保留計數與版本集合摘要。沒有讀取影像、深度、遮罩、帳號內容或稽核本文。
- 使用 `versions=true` 與 `softDeleted=true` 的獨立查詢，完整處理分頁；空頁只要仍有 nextPageToken 就繼續。
- 403、400、逾時、缺少欄位、重複頁碼／版本、來源外物件、超出請求／頁數／項目／時間界限，都保持未知或不完整，不輸出零筆結論。
- 前後讀 bucket metageneration 與相關政策，變更時拒絕完成；這不能鎖住其他 writer。掃描也不能證明已永久刪除或 provider 不再保留的歷史。
- 一次 collector 只能使用一次；只有 GET。GCS list 權限本身是 bucket 範圍，prefix 篩選不能冒充 IAM 隔離。

## 驗證及下一步

25 項新的合成測試涵蓋完整分頁、檔名前綴、歷史版本／軟刪除、權限與錯誤、界限、來源範圍、metadata 遮罩及政策變動。測試 transport 禁止網路。另將前輪 54 項 bootstrap／adapter 一起重跑，共 79 項；不得與前輪總數相加。

部署時應明列保留的研究來源與新個人服務來源，說明二者身分及權益差異。若發現同一個人服務曾有帳號、訂閱關聯或用量，必須改走真實基準遷移。本輪已有受限的來源觀察及部署歷史佐證，但尚未完成新服務啟用時的 writer 封鎖、有效 IAM 及正式簽署清冊，所以本輪結果不放行初始化；不需要為新的獨立帳本而清空或停止舊研究紀錄。

下一個固定部署方案必須包含實際資源、operator／observer 保管、封閉入口、來源範圍與有界初始化／回復，不能單憑本機測試通過開流量。真實 Apple Sandbox、共用 KEK 歷史副本退休及完整刪帳仍待完成。

## 官方參照

- [GCS Objects: list](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/list)：版本與軟刪除參數分開；分頁不能只看當頁是否為空，`softDeleted=true` 需要對應政策。
- [Cloud Run revisions.list](https://docs.cloud.google.com/run/docs/reference/rest/v2/projects.locations.services.revisions/list)：`showDeleted` 包含的是已刪除但尚未過期的資源，不能代表永久完整的部署歷史。

- [Cloud Audit Logs](https://docs.cloud.google.com/logging/docs/audit)：Admin Activity 記錄資源設定變更；本次只讀方法、資源與時間，不讀請求本文或操作者個資。
