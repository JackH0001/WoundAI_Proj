# WoundAILite 個人服務與研究撤回的身分核對

## 可重現的問題

iOS 將個人服務與研究服務的 App Attest 身分分開保存。登記時，各服務獨立產生 installation ID。在 fa827a5 的私有清理程序，個人登入的 ID 卻也用來選擇研究參與、目前媒體與歷史版本。同機取得兩個不同的合成登記 ID 後，程序回報「已關閉連結的研究安裝」，實際研究 ID 仍可寫入。舊測試用了相同字串，因而無法發現這個差異。

## 私有程序的變更

- 帳號的 Apple 身分、個人服務的裝置 ID 與研究參與 ID 有各自的來源。核對同一個字串不能建立跨服務關聯。
- 私有程序只接受兩份針對同一項撤回作業的 Ed25519 證明。個人與研究服務使用不同的驗證公鑰，也必須與執行及停止作業的操作員金鑰分開。簽署內容包含帳號範圍、帳號雜湊、兩個安裝 ID、個人裝置登記收據、研究桶與確切刪帳操作編號。角色名稱也參與簽署。驗證公鑰及整份設定檔由部署端釘選。
- 同一個私有設定檔至多接受 100 筆證明。相同作業與個人安裝不得有兩個不同的研究對象。同一研究對象也不能指向不同帳號或不同個人安裝。不明確的關係需要另行核對。在此版本中，同一帳號尚缺證明時，該帳號的研究清理停在該處，可從原進度續接。獨立的研究撤回仍可使用。
- 在變更研究狀態前，把已核對的對象與證明雜湊固定在該帳號、該次刪帳及該裝置的稽核中。重新啟動或重試不能改用另一個對象。研究媒體處理及歷史版本清理都沿用該研究 ID。讀取舊資料和銷毀媒體也要通過相同查核。
- 舊設定未提供證明時，程序保留資料與進度，回報 `pending / verified_research_link_required`。現有獨立研究參與不會因此被停用。新增的計畫版本區分舊稽核。舊版本已寫入的 retirement 不得自動改寫或用於新的刪除，有衝突的舊紀錄需要個案核對。
- 同意刪帳、要求獨立研究撤回、封鎖新研究寫入、處置目前媒體、處置歷史版本，各有獨立證據。這項修正不證明所有備份或機構封存庫已清理。

## 外測前尚須接上的路徑

本次變更是私有清理程序和唯讀清冊端的驗證。App 仍須能在使用者明確選擇撤回指定研究資料時，使用原個人服務與原研究服務各自既有的已驗證身分取得這兩份證明。不得只讀取 Apple 電郵比對、將這台手機上的匿名歷史自動連結至帳號、建立新研究身分代替原身分，或讓同一個操作者代替兩個服務簽證。沒有原研究身分或未同意建立關聯時，清楚呈現未核對範圍及現有獨立撤回管道。

正式簽發端應從驗證後的請求取得帳號／安裝 ID，對此用途重新取得明確確認。限短效配對要求，對重送提供同一筆回執。在凍結的私有作業中才可使用持久的已核對證據，需有各自保管及輪替的簽發金鑰。仍須實機驗證共用手機換帳號、不同研究環境、網路中斷、重新加入與原始研究資料已不存在的情況。

## 重跑

在 repo 的 Python 測試環境，設定既有的 `tools`、`engineering/phase2`、`Backend/Flask` 及 repo 根目錄為模組搜尋路徑，以 `WOUNDAI_STORE=local` 執行以下測試。

```sh
python -m unittest -v test_lite_cross_origin_research
python -m unittest -v test_lite_account_research_closure test_lite_research_media_disposition test_lite_research_history test_lite_account_data_inventory test_lite_disposition_startup test_lite_disposition_package
```

所有測試的簽章、顏色影像、標註、金鑰與儲存區都是合成或本機提供者。覆核時請查核缺少證明時的進度。兩個 ID 不同時，只有正確研究對象的寫入被封鎖。修改其中任一個 ID、簽章、帳號、桶或刪帳操作都應被拒。重試不得改變已固定的研究對象。外人的媒體及原有稽核保持完整。
