## 第一段：一定編譯失敗

### 1. `try?` 對「throws 且回傳 Optional」的函式會壓平（SE-0230）

`PhiCrypto.encryptBytes(_ plain: Data?) throws -> Data?`（`Core/PhiCrypto.swift:170`）同時 throws 且回傳 Optional。Swift 5 起 `try? f()` 的結果是**壓平後的單層** `Data?`，不是 `Data??`。所以第一個 `let` 綁完就已經是非 Optional 的 `Data`，第二個 `let` 對非 Optional 做條件綁定，編譯器直接拒絕。

| 檔案:行號 | 現況 | 編譯器訊息 |
|---|---|---|
| `Core/LocalImageStore.swift:28` | `guard let enc = try? PhiCrypto.encryptBytes(jpeg), let enc = enc else { return nil }` | `initializer for conditional binding must have Optional type, not 'Data'` |
| `Core/LocalImageStore.swift:77` | `guard let enc = try? PhiCrypto.encryptBytes(bytes), let enc = enc else { return nil }` | 同上 |

修法（語意完全不變——`encryptBytes` 只有 throw 時 `try?` 才會產生 nil）：

```swift
// LocalImageStore.swift:28
guard let enc = try? PhiCrypto.encryptBytes(jpeg) else { return nil }

// LocalImageStore.swift:77
guard let enc = try? PhiCrypto.encryptBytes(bytes) else { return nil }
```

### 2. `Core/Entities.swift` 缺 `import Security`

`Entities.swift` 檔頭只有 `import Foundation`，但 `WoundCase.newWdCode()`（第 66 行）用了 `SecRandomCopyBytes` 與 `kSecRandomDefault`。這兩個符號宣告在 Security framework，Foundation 不 re-export。

對照組：`Core/PhiCrypto.swift` 用同一支 API，而它第 3 行有 `import Security`。

```swift
// Entities.swift 檔頭
import Foundation
import Security
```

### 3. `Pipeline/WoundAnalyzer.swift` 的 `public` 簽名洩漏 `internal` 型別

`public func run(...) async -> MeasureResult`（第 37–41 行），但 `MeasureResult`（`WoundPipeline.swift:26`）與它的成員型別 `PushScore`（同檔第 18 行）都沒有 `public`。

```
error: method cannot be declared public because its result uses an internal type
```

三位審查者都獨立抓到這一條。修法二選一，**建議降級**——這個型別只在 App target 內部使用，`public` 本來就沒有意義，而且 `WoundAnalyzer` / `WoundSegmenter` 目前**沒有任何實作者或呼叫端**（UI 全走後端 `classify`），改動風險是零：

```swift
// WoundAnalyzer.swift:16
final class WoundAnalyzer {
    private let student: WoundSegmenter
    private let wsm: WoundSegmenter?
    init(student: WoundSegmenter, wsm: WoundSegmenter? = nil) { self.student = student; self.wsm = wsm }

// WoundAnalyzer.swift:37（後續參數縮排跟著減 7 格）
    func run(image: CGImage,
             markerCorners: [CGFloat]?,
             exudate: Int?,
             tissueFracOverride: [String: Double]? = nil,
             cloudEscalate: ((CGImage) async -> [Bool])? = nil) async -> MeasureResult {
```

另一條路是把 `PushScore` 與 `MeasureResult` 都改成 `public struct` 並補手寫 `public init`（public struct 的 memberwise init 預設仍是 internal），改動較大，不推薦。

### 4. `.task {}` 內同步呼叫 `@MainActor` 方法

`AppState`（`UI/WoundAIApp.swift:26`）是 `@MainActor final class`，所以 `refreshBanner()` 與 `@Published var chosenCase` 都是 main-actor 隔離。

而 SwiftUI 的 `View.task(priority:_:)` 參數型別是 `@escaping @Sendable () async -> Void`——**`@Sendable` closure 不繼承外層 actor 隔離**，body 是 nonisolated async。跨隔離呼叫沒有 `await` 就是硬錯誤：`expression is 'async' but is not marked with 'await'`。

| 檔案:行號 | 現況 | 修法 |
|---|---|---|
| `UI/WoundAIApp.swift:61` | `app.refreshBanner()` | `await app.refreshBanner()` |
| `UI/CaseAndConsentViews.swift:118` | `app.refreshBanner()` | `await app.refreshBanner()` |
| `UI/CaseAndConsentViews.swift:328` | `if let c = app.chosenCase { rows = await app.repo.measurements(caseId: c.id) }` | `if let c = await app.chosenCase { rows = await app.repo.measurements(caseId: c.id) }` |

### 5. 測試從同步情境呼叫 `@MainActor` static method

`MeasureViewModel`（`UI/MeasureFlowView.swift:11–12`）標了 `@MainActor`。這裡有個容易踩的差異：**`actor` 的 static member 是 nonisolated，但 `@MainActor` 標在型別上會連 static member 一起隔離**（SE-0316）。

`ContractTests.swift:185` 在同步的 `func testAdvisoriesCoverSilentFailureModes()` 裡呼叫 `MeasureViewModel.advisories(r, clinical: true)`：

```
error: call to main actor-isolated static method 'advisories(_:clinical:)' in a synchronous nonisolated context
```

修法二選一。**建議改測試端**（一行）：

```swift
// ContractTests.swift:175
@MainActor
func testAdvisoriesCoverSilentFailureModes() {
```

或改 App 端——`advisories` 是純函式，不碰任何 `@Published`，標 `nonisolated` 是安全的：

```swift
// MeasureFlowView.swift:68
nonisolated static func advisories(_ r: ClassifyResult, clinical: Bool) -> [String] {
```

## 第二段：建置設定阻塞（不是編譯錯誤，但會讓你連 build 都跑不起來）

### `project.yml` 沒有 `schemes:` 區塊

XcodeGen 預設**不產生 shared scheme**，但 `BUILD_RELEASE.md` 教的指令是 `xcodebuild test -scheme WoundMeasurementApp`。剛 `xcodegen generate` 完直接跑會得到：

```
xcodebuild: error: The project ... does not contain a scheme named "WoundMeasurementApp".
```

在 Xcode GUI 開一次會自動建 scheme，但那是 user scheme、不進 git，CI 上會重現同一個錯誤。貼在 `project.yml` 最後：

```yaml
schemes:
  WoundMeasurementApp:
    build:
      targets:
        WoundMeasurementApp: all
        WoundMeasurementAppTests: [test]
    run:
      config: Debug
    test:
      config: Debug
      gatherCoverageData: true
      targets:
        - WoundMeasurementAppTests
```

順帶兩個保險（零成本）：

```yaml
  # WoundMeasurementAppTests 的 settings.base 底下
        GENERATE_INFOPLIST_FILE: YES
        PRODUCT_BUNDLE_IDENTIFIER: com.woundmeasurement.app.tests
```

以及第一次跑通編譯時先繞過簽署（`DEVELOPMENT_TEAM: LY2F24ZM68` 若不在你的 Xcode 帳號裡，某些版本連 Simulator 都會卡簽署）：

```bash
xcodebuild test -project WoundMeasurementApp.xcodeproj \
  -scheme WoundMeasurementApp \
  -destination 'platform=iOS Simulator,name=iPhone 15' \
  CODE_SIGNING_ALLOWED=NO
```

## 第三段：可能失敗（附觸發條件與不確定的理由）

### A. `CaseAndConsentViews.swift:167 / 182 / 388` — 兩位審查者結論不同，我照實列

這三處是 `private func ... async` 裡呼叫 `app.refreshBanner()`（沒有 `await`），方法本身宣告在 `struct CaseSelectView: View` / `BackendSettingsView` 內。

- 若你的 **Xcode 15 / iOS 17 SDK**：`View` 協定本身還不是 `@MainActor`（只有 `body` 是 `@MainActor(unsafe)`），這三個方法是 nonisolated → **會編譯失敗**
- 若 **Xcode 16 以後**：`View` 是 `@MainActor @preconcurrency protocol`，整個 struct 被推導成 `@MainActor` → **合法**

沒有 macOS 可以核對 `.swiftinterface`，所以無法斷言。但**兩種 SDK 都安全的寫法**是加上 `await`（若外層已是 `@MainActor`，多出來的 `await` 只是 `no 'async' operations occur within 'await' expression` 這個無害警告）。

更乾淨的做法是把這幾個會碰 `AppState` 與 `@State` 的 async 輔助方法一律標 `@MainActor`，一次解掉編譯問題**與**下面第四段的背景執行緒寫 `@State` 問題：

```swift
// CaseSelectView
.task { await load() }

@MainActor private func load() async {
    patients = await app.repo.listPatients()
    _ = await ConsentSync.retryPending()
    app.refreshBanner()
}

@MainActor private func choose(_ p: Patient) async { … }
@MainActor private func createPatient() async { … }
@MainActor private func createCase(_ p: Patient) async { … }
@MainActor private func sign(_ p: Patient, care: Bool, train: Bool, png: Data?) async { … }
@MainActor private func withdraw(_ p: Patient) async { … }

// TimelineView
.task { await load() }
@MainActor private func load() async {
    if let c = app.chosenCase { rows = await app.repo.measurements(caseId: c.id) }
}

// BackendSettingsView
@MainActor private func save() async { … }

// RootView（WoundAIApp.swift）
.task { await boot() }
@MainActor private func boot() async {
    _ = await ConsentSync.retryPending()
    app.refreshBanner()
    let backend = BackendClient(baseUrl: AppSettings.backendURL())
    _ = try? await backend.health()
}
```

加了 `@MainActor` 之後，原本已經寫對的 `await app.repo.xxx()`、`await ConsentSync.xxx()`、`try await c.health()` 全部維持不變。

### B. 型別推導超時 — `UI/MeasureFlowView.swift:275–285`

`ResultCard` 有三段 `Text("…" + "…" + "…")` 的寫法，其中第 278–283 行是 4 個 `+` 串接、每段各有字串插值。`String` 的 `+` 有多個重載、每個插值有 `String`/`LocalizedStringKey` 兩種候選、`Text` 本身兩個 init 重載——搜尋空間約 10³–10⁴ 量級，正好落在實測會超時的區間：

```
error: the compiler is unable to type-check this expression in reasonable time;
       try breaking up the expression into distinct sub-expressions
```

這個錯誤訊息不會告訴你是哪一段，所以事前拆掉最划算。把型別釘死成 `String` 並改用純插值（不用 `+`）：

```swift
private var tissueLine: String {
    let g = pct(result.tissueFrac["granulation"])
    let s = pct(result.tissueFrac["slough"])
    let n = pct(result.tissueFrac["necrosis"])
    let e = pct(result.tissueFrac["epithelial"])
    let o = pct(result.tissueFrac["other"])
    return "組織　肉芽 \(g)・腐肉 \(s)・壞死 \(n)・上皮 \(e)・其他 \(o)"
}

private var pushLine: String {
    let p = result.pushPartial.map { "\($0)" } ?? "—"
    return "PUSH：\(p)（面積＋組織；滲液須醫師輸入才算得出總分）"
}
```

body 內改成 `Text(tissueLine).font(.footnote)`、`Text(pushLine)`。第 284–285 行（1 個 `+`）風險較低，一併抽出來也只是兩分鐘的事。

### 一條執行期缺陷（值得順手修）

`Core/Entities.swift:66–68` 的 `_ = SecRandomCopyBytes(...)` 丟棄了 OSStatus。亂數失敗時 4 個位元組維持全 0，`newWdCode()` 對每一個個案都回 `"WD-00000000"`，撞上 `index_wound_cases_wdCode` 的 UNIQUE，`createCase` 重試 5 次後 `throw RepoError.wdCodeCollision`——醫師看到的是「WD-code 配發失敗」，而真因完全不在訊息裡。

```swift
static func newWdCode() -> String {
    var bytes = [UInt8](repeating: 0, count: 4)
    if SecRandomCopyBytes(kSecRandomDefault, bytes.count, &bytes) != errSecSuccess {
        // 退回 UUID（仍為系統亂數）；絕不可讓 4 個位元組維持全 0
        let u = UUID().uuid
        bytes = [u.0, u.1, u.2, u.3]
    }
    return "WD-" + bytes.map { String(format: "%02X", $0) }.joined()
}
```

## 一則需要留意的架構事實

舊樹的「隔離」**是靠 `project.yml` 的 sources 清單維持的，不是靠檔案系統**。`_quarantine/` 底下只有 4 個舊 Pipeline UI 檔與 9 個舊測試檔；真正的 91 個舊檔案還原封不動躺在原位：

| 目錄 | 檔數 |
|---|---|
| `WoundMeasurementApp/Modules/` | 44 |
| `WoundMeasurementApp/Views/` | 24 |
| `WoundMeasurementApp/Models/` | 10 |
| `WoundMeasurementApp/Services/` | 9 |
| `WoundMeasurementApp/Analysis/` | 2 |
| `WoundMeasurementApp/Utils/` | 2 |

任何人日後在 `project.yml` 的 `sources:` 加一行，那 58 組 `invalid redeclaration` 會一次全部回來。Android 那邊改副檔名為 `.kt.disabled` 的做法在檔案系統層面更難誤觸——這裡值得考慮跟進。

## 建議的執行順序

1. 套第一段的 9 個必修（6 個是加 `await` 或 `@MainActor`、2 個是刪多餘的 `let`、1 個是把 `public` 拿掉）
2. 補 `project.yml` 的 `schemes:` 區塊——否則 `xcodebuild -scheme` 連跑都跑不起來
3. 順手加三個 import：`Entities.swift` 的 `Security`（必修）、`CaseAndConsentViews.swift` 的 `UIKit`、`LocalImageStore.swift` 的 `ImageIO`（後兩者是零成本保險）
4. 順手把 `ResultCard` 的三段 `Text(… + … + …)` 抽成 computed property——這是唯一可能出現「type-check 超時」的地方，而那個錯誤訊息不會告訴你是哪一行
5. 第一輪 `xcodebuild` 加 `CODE_SIGNING_ALLOWED=NO`
6. 剩下的 deprecated 警告最後再清

**這份報告是讀出來的，不是編出來的。** 上面 9 個必錯修掉之後，最可能還會冒出來的是 SwiftUI `body` 的型別推導超時——那種問題無法靜態預判，只能靠實際編譯。把錯誤貼回來即可逐項修。
